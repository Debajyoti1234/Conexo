# Phase 8.2 Hotfix — Profile Complete → MainShell

## Goal
After a new/incomplete user completes the mandatory profile flow, the app must navigate to `MainShell` and remove `ProfileCreationScreen` from the stack. Today it saves the profile, plays the "Profile complete" overlay, then calls `Navigator.maybePop()` on a root route (no-op) → stuck.

## Root Cause (verified)
- `AuthGate.navigateToTarget({ProfileRepository? repository})` is invoked with NO argument from `splash_screen.dart`, `login_screen.dart`, `phone_auth_screen.dart`.
- Inside, status is computed via a throwaway `const SupabaseProfileRepository()`, but the original `repository` (still `null`) is passed to `ProfileCreationScreen(repository: repository)`.
- Result inside `ProfileCreationScreen`:
  - `repository == null` → `_complete()` persists via the `const LocalProfileRepository()` fallback (mandatory flow wrongly uses local, not Supabase).
  - `onComplete == null` → after the completion overlay it calls `Navigator.of(context).maybePop()`.
  - Screen was installed via `pushReplacement` (splash) / `pushAndRemoveUntil` (login/phone) → it is the only route → `maybePop()` is a no-op → STUCK.

## Blast Radius (verified)
- `ProfileCreationScreen(` constructed only at:
  - `lib/core/supabase/auth_gate.dart:21` (mandatory gate).
  - `lib/features/profile/profile_creation_screen.dart:433` (`premiumProfileCreationRoute`) — does NOT pass `onComplete`.
- `onComplete` referenced only inside `profile_creation_screen.dart`. No external caller passes it, so changing its type is safe.
- `AppRouter.slideRoute<T>(Widget page)` exists (`lib/app/router/app_router.dart`).
- `MainShell` is `const`-constructible (`lib/features/main_shell.dart`).

## Allowed Files (only these two)
1. `lib/core/supabase/auth_gate.dart`
2. `lib/features/profile/profile_creation_screen.dart`

## Design Decision
`AuthGate` has no `BuildContext`, and callers cannot be modified. Therefore the `onComplete` callback must RECEIVE a `BuildContext` from `ProfileCreationScreen` (which owns a context under the root Navigator). Change `onComplete` type from `VoidCallback?` to `void Function(BuildContext context)?`.

## Edits

### 1) `lib/core/supabase/auth_gate.dart`
- Add import: `import '../../app/router/app_router.dart';` (keep existing `main_shell.dart` import).
- Reuse ONE repository instance and never fall back to Local for the mandatory flow:

```dart
static Future<Widget?> navigateToTarget({ProfileRepository? repository}) async {
  final repo = repository ?? const SupabaseProfileRepository();
  final status = await repo.checkProfileStatus();

  switch (status) {
    case ProfileStatus.missing:
    case ProfileStatus.incomplete:
      return ProfileCreationScreen(
        repository: repo,
        onComplete: (context) {
          Navigator.of(context).pushAndRemoveUntil(
            AppRouter.slideRoute(const MainShell()),
            (route) => false,
          );
        },
      );
    case ProfileStatus.complete:
      return const MainShell();
    case ProfileStatus.error:
      return null;
  }
}
```

Notes:
- `repo` is passed to `ProfileCreationScreen` (satisfies "same SupabaseProfileRepository instance" and "no Local fallback in mandatory flow").
- `ProfileStatus.complete` still returns `const MainShell()` directly (existing completed user).
- `ProfileStatus.error` still returns `null` (caller keeps existing retry/SnackBar behavior).

### 2) `lib/features/profile/profile_creation_screen.dart`
- Change the field type:
  - From: `final VoidCallback? onComplete;`
  - To:   `final void Function(BuildContext context)? onComplete;`
- In `_complete()`, replace the tail (currently):

```dart
    await Future<void>.delayed(const Duration(milliseconds: 1500));
    if (!mounted) return;
    widget.onComplete?.call();
    Navigator.of(context).maybePop();
```

  with:

```dart
    await Future<void>.delayed(const Duration(milliseconds: 1500));
    if (!mounted) return;
    final onComplete = widget.onComplete;
    if (onComplete != null) {
      onComplete(context);
    } else {
      Navigator.of(context).maybePop();
    }
```

Preserve everything else in `_complete()` exactly:
- `_saving` guard, 700ms delay, `AuthService.currentUser?.id` null guard.
- `UserProfile.fromDraft(_draft, id: userId)`, `repo.saveProfile(profile)`, `repo.clearDraft()`.
- `setState(_completed = true)` + 1500ms overlay animation (`_CompletionOverlay`).
- Local draft methods (`_checkForDraft`, `_onDraftChanged`, `_discardDraft`) UNCHANGED — they keep using `widget.repository ?? const LocalProfileRepository()`; with the Supabase repo injected, its draft methods delegate to Local, so local draft behavior stays intact.

## Behavior After Fix
- New user: Splash → session → `missing` → ProfileCreationScreen (Supabase repo) → complete → saved to Supabase → existing "Profile complete" overlay → `onComplete(context)` → `pushAndRemoveUntil(MainShell)` → MainShell (ProfileCreationScreen removed).
- Existing completed user: Splash → session → `complete` → MainShell directly.
- Incomplete user: Splash → session → `incomplete` → ProfileCreationScreen.
- `premiumProfileCreationRoute` (no `onComplete`) → still uses `maybePop()` (unchanged).

## Out of Scope / Must NOT Change
- No UI redesign; overlay/animation untouched.
- No Supabase schema/migration/database changes; do NOT run `supabase db push`.
- No auth logic, validators, or unrelated files.
- Do not modify `splash_screen.dart`, `login_screen.dart`, `phone_auth_screen.dart`.

## Validation
- Run `flutter analyze` (expect: no issues).
- Confirm the two callers still compile (they call `navigateToTarget()` with no args — signature unchanged).

## Risks / Edge Cases
- `Navigator.of(context)` inside `onComplete` resolves to the app root Navigator (ProfileCreationScreen adds no nested Navigator) → `pushAndRemoveUntil(..., (route) => false)` guarantees the creation screen is not left underneath.
- `mounted` is checked immediately before invoking `onComplete`, so the captured `context` is valid.
- Type change to `onComplete` is safe: only `AuthGate` will pass it; `premiumProfileCreationRoute` leaves it null.
